# 阶段 E 落地细则（E1–E3）

样张（E0）通过后再读本册。E0 的门槛留在 `SKILL.md`：**先做一屏给人看，再铺开。**

## E1 设计 token

| 技术栈 | 落地方式 |
|---|---|
| 原生 CSS / SCSS | `:root` 定义三层 token：Primitive 原值 → Semantic 语义 → Component 组件别名，UI 只写 `var(--…)` |
| Tailwind | 语义 token 进 `theme`（颜色 / spacing / fontSize / lineHeight / borderRadius），标 v3 还是 v4 |
| CSS-in-JS / 其它 | Design Tokens 抽象层（JSON），一处定义渲染成多端格式 |

- 语义色族补「整套」：浅底 / 本体 / 深字 / rgb 三元组（见 G7）。
- **动效另给「拼好的 transition」token**，不让人自己拼（见 G5）。
- **交互常量也进 token**：命中目标下限、拖拽阈值、层级 `z-index`、断点——它们和颜色一样会被各处写字面量。
- `z-index` 默认阶梯见 `defaults.md`（六带、档间留大间隔、带内细分不跨带）。
- token 加注释说明用途；组件里不出现裸值；**由几何反推的值、以及「改它要连带重算什么」写进注释**。

## E2 组件规格表

- 每个核心组件（按钮 / 输入框 / 开关 / 卡片 / 菜单项 / 弹窗 / 折叠 / 提示 / 进度 / 列表行…）给**状态组 × 属性**（背景 / 文字 / 边框 / 阴影 / 圆角 / 焦点环 / 内距 / 字号），值一律引用 token。
- 表分两层：**通则**（悬停总则、图标状态色、按压反馈）+ **逐组件速查表**（只写通则没覆盖的）。
- 状态残缺是最大的不一致来源：每个组件过一遍 G4 的状态清单，缺哪个补哪个。
- **交互与动效也进规格表**：命中区、键盘操作、进 / 出场用哪个 transition token、是否需要可中断。

## E3 规范文档

- 章节按需取，但**至少含**：设计原则（只写指向）、语义色与映射、度量档位表、状态模型与悬停总则、体验与任务流（三态 / 错误预防）、交互（主输入 / 命中目标 / 键盘与焦点 / **表单**）、**反馈与确认（各通道 + 确认框层级，见 G13）**、**文案与用词（见 G14）**、动效（判据 / 档位 / 降级）、图标策略、**图表与表格（见 G11）**、组件速查表、无障碍清单、改动自检清单、token 增改流程。
- **改动自检清单分两段**：无障碍底线（不得退化）与设计系统一致性——性质不同，混在一起分不清哪些是硬性。
- 写值前对照真实运行画面 / token 定义核一遍（工作前提 1）。

## E4 迁移老代码（有乱象时）

- 先清裸值 / 旧档再立规矩：把裸 hex、非档位 px、自造时长缓动、混用图标列成清理单；新增控件不得照抄老写法。
- 分批替换，每次可回退。
