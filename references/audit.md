# 阶段 F 审计清单

入口规则留在 `SKILL.md`：**按「界面里的实例」走，不按「规则条目」走**——先把每个可交互实例列成清单，再逐条核对。下面是清单里的九项检查。

1. **静态审计**：token 外扫裸 hex / rgb；扫非档位 px / 行高 / 圆角 / 时长 / 缓动；扫 emoji / Unicode 字形 / 临时 SVG 当图标；核对组件五态；关键文字对**按实际底色**算对比度。
2. **三处一致**：规范 ↔ token ↔ 代码值一致，旧值不漂移。
3. **截图 / 运行审计**：关键页 + 各态（hover / 按下 / 禁用 / 加载 / 键盘焦点）。**按下态要真按住测**（见 P2）。
4. **体验走查**（按 A6 复走）：主路径步数有没有变多；三态是否都在；**只用键盘**走完一次主任务；每个按钮文字脱离上下文读一遍；报错是否说了「怎么办」。
5. **动效审计（要量，不能只看代码）**：用 `getComputedStyle` 读**实际生效**的时长与缓动，跟项目 token 对账（写的值和渲染出来的常常不是一回事），判据按 `defaults.md` 的动效节与 G5。**多套实现对账**：CSS 曲线与图表库 / JS 库实际拿到的 `easing` 必须同族同档。另查：高频操作无不必要的动画；可中断的动效用 transition（P11）；`prefers-reduced-motion` 下**降级而非消失**（开 reduced-motion 的上下文真跑一遍）。
6. **图表审计**：逐个 canvas 核对——同一套库、同一份封装；对照 G11（ΔE、坐标轴令牌、图例、从 0 起、深色另给色、条内文字按本条底色、空态 / 单点 / 全 0 退化、可访问名）。表格对照 G11.8。
7. **无障碍审计**：逐项对照 G12——Tab 序与焦点环、状态不只靠颜色、图标按钮的 `aria-label`、`aria-expanded` / live region、弹窗 `role=dialog`、文字可选中、reduced-motion 降级；原生控件的接管情况按 P16 逐个标记「已接管 / 已记录理由」。
8. **反馈与文案专项**：逐条主路径核对——不可逆动作有确认或可撤销，失败不静默，空态给下一步，成功有可见结果；确认框是否真的压过所有普通弹窗（不能靠「普通弹窗层级 + N」）；标题 / 按钮 / 状态词 / 标点按 G14 过一遍，同一动作全流程是不是同一个词。
9. **图标与对齐复测**：按 G9 量——图标墨迹中线与相邻文字行框中线差值 > 0.5px 即算没对齐；同一行多枚图标先彼此墨迹等高，再一起对文字中线。
10. **专项复测**（容易漏的）：浮层互切（P6）、滚动容器焦点环（P4）、拖动路径反馈（P2）、滚动条移入移出（P3）、删除后焦点落点（P12）、内容撑高的浮层开窗（P14）。

**只报不合规点 + 修法**给用户，不静默改对外文档。

**退出条件**：清单里每个实例都有归属——落在某条规则下且渲染符合，或已作为例外写明理由；不合规点要么修完，要么用户明确接受。**存在「既没归类也没例外」的行，审计就不算完。**
