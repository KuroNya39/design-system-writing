# 设计语法 · 数据与无障碍（G11、G12）

规则集分四册，G 编号跨文件连续。本册管图表、表格与无障碍；流程见 `grammar-flow.md`，视觉见 `grammar-visual.md`。

## G11 数据展示（图表与表格）

**图表不是「画出来就行」。** 在数据类产品里它占的面积往往比正文还大，一致性比组件更值得先定——而它最容易被当成「技术活」跳过。

### G11.1 选型（B1 必问，别自己定）

- **一套库、一个版本，全站固定**。中途换库 = 所有配置重写。选型看四件事：① 技术栈（原生 HTML 用 Chart.js / ECharts，React 用 Recharts / visx）；② 数据量（上千个点要能走 canvas 或抽稀）；③ 需要的图型（地图、桑基、关系图只有 ECharts / D3 这类有）；④ 体积与离线。
- **配置写法也要统一**：**抽一层自己的封装**，颜色 / 字号 / 网格线 / tooltip / 动效全部走封装，调用处只传数据。没有封装层，配置一定散落各处。
- **别混多套图表库**：并存时 tooltip 样式、动效曲线、响应式行为三处最先露馅。

### G11.2 图型选择

| 要表达什么 | 用什么 | 不要用什么 |
|---|---|---|
| 比大小（分类不多） | 柱 / 条形 | 饼图 |
| 看趋势（时间序列） | 折线 | 柱（点多时糊成一片） |
| 看占比（分类 ≤ 5） | 饼 / 环 | 饼（> 5 类） |
| 看构成随时间变 | 堆叠柱 / 堆叠面积 | 多张饼 |
| 看分布 | 直方 / 箱线 | 折线 |
| 看相关性 | 散点 | 折线 |
| 看二维交叉（部门 × 等级） | 热力矩阵 | 一堆小饼 |

- **分类超过 6–7 类就别用饼图**：人眼比角度不准。改**横向条形**（还能排序）。
- **分类名是中文或名字长时用横向条形**（`indexAxis:'y'`），横排不用把标签转 45°。
- **一屏一个「主图」**：并排四五个同等大小的图，等于没有重点。

### G11.3 坐标轴与网格线

- **能去掉的都去掉**：纵轴刻度线、外框、绘图区背景色一律不加。**网格线只留水平**。
- **坐标轴不是数据，用专门的 `gridline` / `baseline` 令牌**，不要用正文色。
- **数值轴从 0 起**（柱状图必须；折线要强调幅度时可截断，但**必须在轴上标出来**）。
- **分类多时标签抽稀**，别让标签叠成一团。

### G11.4 图例与标注

- **单序列不要图例**——标题已经说了这是什么。
- **图例位置全站固定**（都在顶部或都在底部）。
- **能直接标在图上就别用图例**（折线末端直接写名字）。
- **数据标签只在点少时开**（≤ 12 个点）；点多了改 hover tooltip。

### G11.5 配色

- **图表填充取分类色板，语义色专留给语义。** 带好坏方向的才用红绿；别拿红绿当两个普通分类。
- **同一张图内相邻色 ΔE 要够大**（≥ 15，CIEDE2000）。**按用途挑色，不按 `palette[0..n]` 顺序取**——顺序取最容易拿到两个相近色。
- **有顺序的档位（评分、等级）用档位色阶**，不用分类色板。
- **深色模式要另给色值**：同一个分类色垫到深底上会掉一档。
- **条内文字颜色按「这一条自己的底色」判**，不是按主题；按主题缓存结果，别每帧读 `getComputedStyle`。

### G11.6 状态与退化

- **三态齐全**：空态（给下一步）、加载态、错误态。**空态不要画一个空坐标系**。
- **单点数据不要画折线**：退化成「一个点 + 数值」，或直接显示数字。
- **全部为 0 时给一句话说明**，别画一排高度为 0 的柱子。
- **数值超长时缩写或省略**（`12.3万`），别让标签撑破卡片。
- **图表的空态文案与页面其他空态同款**，别图表一套、列表一套。

### G11.7 动效与无障碍

- **图表入场走 `slow` 档、与页面入场同族缓动**（见 G5）；**键盘触发的切换不做动画**。
- **图表不能是唯一的信息通道**：关键数值在图旁用文字重复一次。
- **canvas 要给可访问名**：`role="img"` + `aria-label` **概括结论**（「各部门在职人数，研发 120 人最高」），不是只写「柱状图」；旁边有明细表时用 `aria-describedby` 指过去。
- 图表元素可点时按 G4 悬停总则处理；但**按下态可以不给**——真正被按的是图里那一条，给整块加底色会把「我点的是这条」抹掉（例外写明理由）。

### G11.8 表格

- **数字列右对齐 + `tabular-nums`，文本列左对齐**；表头与内容同列对齐。
- **可排序列在表头给排序指示**（箭头 + `aria-sort`），默认排序写明。
- **行操作放行尾固定位置**；一行不超过 2–3 个按钮，其余收进「更多」。
- **空表给空态**（说明 + 新建入口），不要只留一排表头。
- **整行可点时，行内按钮要 `stopPropagation`**，否则点按钮会顺带触发行点击。
- **横向滚动时首列（标识列）可固定**，让用户知道自己在看哪一行。

## G12 无障碍（可及性）
| 语法 | 落地检查 |
|---|---|
| **键盘可达**：所有功能 Tab 可达并可用 Enter / 空格 / 方向键；遍历顺序符合视觉顺序，不跳焦点。 | 全交互过一遍 Tab 序；焦点环可见。 |
| **焦点环一律可见**：键盘到达时必现，鼠标点击时不显示。程序聚焦的定位标题 / 弹窗只是读屏落点，不画环。滚动容器里的环要留余量（见 P4）。 | 逐个可 Tab 元素聚焦看一眼；滚动容器内重点查。 |
| **不只靠颜色**（见 G7）：状态差异双通道。 | 错误 / 必选 / 连接状态都有文字或图标相伴。 |
| **读屏属性**：纯图标按钮有 `aria-label`，装饰图标 `aria-hidden`，展开用 `aria-expanded`，动态提示用 live region，弹窗 `role=dialog` + `aria-modal`。**不给原生 `title`**——它会弹系统气泡，且不该承载必需信息。 | a11y 语义属性齐；全局搜 `title=`。 |
| **live region 不能嵌套**（见 P8）。 | 容器与元素只有一层标了 live region。 |
| **文字可选中**：正文默认可选中复制，仅交互元素禁用选择。 | 随机划一段正文确认能选中。 |
| **动效尊重 `prefers-reduced-motion`**：关闭或降级为淡入淡出（见 G5）。 | reduced-motion 媒体查询生效。 |
| **命中目标**（尺寸与撑法见 G3 / G9）。 | 最小控件过一遍。 |
