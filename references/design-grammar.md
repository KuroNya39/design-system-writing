# 设计语法（G1–G12）

规则集主体：结构与体验 → 交互 → 视觉 → 数据可视化 → 无障碍，**分层顺序即推理顺序**（工作前提 9）。默认档位表（间距 / 字号 / 行高 / 字重 / 圆角 / 图标 / 阴影 / 动效 / 层级）在 `defaults.md`，本文件只留治理规则。

**以下是默认取舍准则**：写进本项目规范前先整体接受，个别项（圆角、密度、动效胃口）可由 B1 的取舍轮覆盖，但**覆盖要留记录**（工作前提 7），不许静默打破。

| 层 | 回答什么 | 章节 |
|---|---|---|
| **结构与体验** | 有哪些东西、怎么走 | G1 布局与信息架构 · G2 体验与任务流 |
| **交互** | 怎么操作、怎么反馈 | G3 交互与输入 · G4 状态模型 · G5 动效 |
| **视觉** | 长什么样 | G6 度量 · G7 色彩 · G8 组件几何 · G9 图标 · G10 造型 |
| **数据可视化** | 数据长什么样、怎么读 | **G11 图表**（数据类产品里它占的面积常比正文大，**与视觉同层、但要单独定**） |
| **底线（横跨三层）** | 谁都不能被排除在外 | G12 无障碍 |

## G1 布局与信息架构（IA）
| 语法 | 为什么 | 落地检查 |
|---|---|---|
| **单列优先（Single-Column First）**：内容默认一列到底；横向确有空间、且并排确有语义时才多列。 | 窄窗与移动端不重排；多列是为「对比 / 配对」服务，不为塞满。 | 断点表里最窄档是一列；无「为了好看硬并排」的列。 |
| **内容列有宽度上限并居中**：正文列设 `max-width` + 自动外边距，宽窗下不横向铺开；上限只在超宽窗口生效，基准宽度内整列流式铺满。 | 行长失控读起来累；上限只在需要时才起作用，不影响窄窗。 | 宽窗拉一下，内容列不离散；窄窗不截断、不重排。 |
| **渐进披露（Progressive Disclosure）**：核心内容先出现、开箱即用；次要 / 高级内容收进折叠、二级页或浮层。 | 首屏只留一条主路径，降低认知负载。 | 首屏 = 主任务可达；进阶项都在折叠 / 二级。 |
| **邻近成组（Gestalt Proximity）**：相关内容放一起，用户会自动视作一组；分组靠间距，不靠描边线框。 | 间距即分组语言；线框是额外的视觉噪音。 | 相关控件间距小档、组间中档、页间大档（见 defaults）。 |
| **留白即层级（Whitespace as Hierarchy）**：重要的东西周围要「空」；拥挤 = 什么都不重要。 | 焦点由周围留白让出。 | 主 CTA 上下留白 > 次要元素；无「到处一样挤」。 |
| **尺寸主导层级**：越大越重要，辅以字重与灰阶；颜色不作唯一层级信号。 | 层级先从字号 / 面积读出，色盲与弱视也可辨。 | 同级组件标题同档同色；页面一眼能排出主次。 |
| **层级公式**：模块标题、字段标签、主 CTA 各定一套「字号 / 字重 / 颜色」组合，同级不许一大一小。 | 逐处临时决定必然漂移；定成公式才能自查。 | 一屏内字号档位 2–3 档；同级标题完全同款。 |

## G2 体验与任务流（UX）
| 语法 | 为什么 | 落地检查 |
|---|---|---|
| **沿用既有约定**（导航在哪、关闭在哪、垃圾桶 = 删除）：不为「创新」牺牲可预测性。 | 用户的心智模型来自他们用过的所有软件；违反约定要额外学一遍。 | 每个交互都能说出「用户在哪见过同样的做法」。 |
| **一屏一个主任务**：每个界面能指出唯一的「主行动」，其余退为次要或下沉。 | 两个并列的主行动等于没有主行动。 | 一屏只有一个实心主按钮（见 G7）。 |
| **主路径最短**：常见任务一步到位，不经过可选项；高级项下沉二级。 | 每多一个必经的次要选择都是一次常态摩擦，而它一天会发生很多次。 | 主任务能数出步数，且没有一步是为了「顺便配置」。 |
| **一次只要求一个决定**：选项多到一屏扫不完就分组或给搜索。 | 选择本身就是成本。 | 长列表有分组 / 搜索 / 合理默认值。 |
| **错误预防优于错误提示**：能禁则禁、能默认就默认、能约束就约束。 | 事后报错比事先不让错更贵。 | 每个提示过的错误，都先问过「能不能从源头不让它发生」。 |
| **破坏性动作给撤销，而非一律弹确认**：只有不可逆且代价高的才拦一次。 | 确认弹窗用滥了会被无脑点过，反而失效。 | 破坏性动作要么可撤销，要么有确认——不是两者都有。 |
| **三态齐全**：每个数据界面都要设计 空态 / 加载态 / 错误态。 | 只设计「有数据」的样子，另外三种一定长得像没做完。 | 三态都能指出来；空态给下一步动作，不是干放一句「暂无数据」。 |
| **操作后立刻有可见反应**（即使结果还没回来），完成后再给终态。 | 无反馈会让用户重复点击。 | 异步动作在 100ms 内进入加载态。 |
| **文案即界面**：按钮写动词 + 结果（「删除 3 项」而非「确定」）；错误说清「发生了什么 + 怎么办」。**界面能说清的事不要推给文档**——不写「详见 README」「请参考说明」。 | 界面上的字是用户唯一能读的东西；让他离开界面去翻文档，等于当场放弃他。 | 按钮文字脱离上下文也读得懂；错误提示不含「出错了」这类零信息句；报错处直接给下一步动作。 |
| **一致性**：同样的事在不同地方同名、同形、同位。 | 每个不一致都要重新学一次。 | 同一个概念全站只有一个叫法。 |

## G3 交互与输入
| 语法 | 为什么 | 落地检查 |
|---|---|---|
| **先定主输入**（鼠标 / 键盘 / 触屏）：交互按主输入设计，其余「可用」即可。 | 三种都做满不现实，且会互相拖累。 | 说得出主输入是什么，且主路径对它最顺手。 |
| **命中目标不小于 24×24**（触屏 44×44）：视觉可以小，可点区不能小。 | 点不中是最挫败的交互失败。 | 过一遍最小控件（撑法见 G9）。 |
| **按下即反馈**：反馈挂在 `pointerdown`，不是 `click`。 | 等到松手才亮，中间那段时间界面像死的。 | 按住不放，是否已经变样。 |
| **瞬时反馈从最后一次交互起算**：会自己消失的确认提示（「已保存」这类），每触发一次就重新计时。 | 按第一次点击起算的话，连点几次反而更早消失——最需要看到它的那一次恰好最短。 | 连点三次同一个按钮，提示是否每次都重新计时。 |
| **悬停只是增强**：不能用悬停承载唯一入口或唯一信息。 | 触屏没有悬停，键盘也不走悬停。 | 把鼠标移开，功能与信息是否仍可达。 |
| **一个手势一次**：手势进行中忽略后续触发点。 | 多指 / 换手会让元素瞬移到第二根手指的位置。 | 拖动中再按一根手指，位置是否跳。 |
| **拖拽 1:1 跟手并尊重抓取点**：从哪儿按住就从哪儿算偏移，不吸附到中心。 | 吸附会立刻拆穿「这就是我拿着的东西」的错觉。 | 从元素边角按住拖，元素是否从边角跟手。 |
| **阈值之后才算拖拽**：小位移当点击，超过阈值（约 4–10px）才进入拖动。 | 手抖会把点击变成微小拖动。 | 轻微移动后松手，是否仍算点击。 |
| **键盘是一等公民**：Tab 顺序 = 视觉顺序；Enter / 空格激活；组内用方向键；Esc 取消。 | 键盘走不通的界面，对键盘用户等于不可用。 | 全程只用键盘完成一次主任务。 |
| **焦点有家可回**：弹窗打开时焦点锁在弹窗内，关闭时还给触发它的元素；删掉元素后焦点移到合理的邻居。 | 焦点丢了，键盘用户就「失踪」了。 | 开 → 关弹窗、删一行，各看一次焦点落点。 |
| **可中断**：进行中的过渡、动画、加载都能被新输入打断，并从**当前值**继续。 | 用户的想法和手势是并行的；界面不该锁住输入。 | 弹窗关到一半再点开，是否从当前位置接管，而不是跳回起点。 |
| **输入约束在所有输入路径生效**：上限 / 格式这类约束，点加减、按方向键、手输、粘贴四条路都得管。 | 只在一条路上拦，换个输入方式就绕过去了；手输是最先被发现的那条。 | 四条路径各输一次越界值。 |
| **危险动作物理隔离**：不与主行动相邻，被推离惯用点击区（见 G8）。 | 手滑的代价不对称。 | 主 CTA 旁边不是删除。 |

## G4 状态模型（完整状态组）

> **核心规则：任何可交互组件定义完整状态组**——一个按钮至少要 默认 / 悬停 / 按下 / 加载 / 禁用 五态；输入框、卡片、开关、菜单项等同理，另按需补 键盘焦点（focus-visible）、选中（selected）。

- 状态词汇表统一：`rest`（静置）`hover` `active`（按下）`focus-visible`（键盘焦点环）`loading` `disabled` `selected`。
- **焦点环只在键盘到达时显示**（`:focus-visible`），鼠标点击不显示。
- **禁用** = 禁用底色 / 禁用字色 + 禁用光标 + 去阴影。

**按压反馈两类**
- 可整体缩放的控件（按钮、分段钮）按下 `scale(.97–.98)`；整行、菜单项、折叠头这类**行级元素用按下底色**，不整体缩放以免内容破碎。
- **按下不单独给色**，统一交给缩放——少了按下的深色，但避免了「悬停变浅、按下又变深」的方向来回。
- **唯一的例外留给主 CTA**：它悬停就往「加深」走，按下再深一档是同方向的第三步，不会来回。**这条例外只属于这一枚**——别的按钮照搬就会出现「有的按下变深、有的只缩一下」。
- 拖动 / 长按路径上的按下观感**不能靠 `:hover`**（见 P2），要由脚本挂状态类。

**悬停总则：浅底加深、深底变浅**（适用于所有有底色的可点面：按钮、下拉项、列表行、菜单项。）

- **适用范围按 `cursor:pointer` 扫，不按「长得像不像按钮」**：卡片、整块可点区、缩略图、可点的图表元素都算。最常见翻车是「按钮统一了、可点卡片各写各的」——卡片往往是后加的，没人把它归进按钮那套规则。**检查**：全站 grep `cursor:pointer` 和所有绑了 click 的容器，逐个归类到「浅底加深 / 深底变浅」，归不进的就是漏网的第三类，必须收编或写明例外。
- **只改底色，不上浮、不加悬停影**：底色浅的（白底、透明、浅色洗涤）加深一档；底色深的（实心主色 / 实心红）变浅一档——「悬停＝更醒目」在两种底色上都成立，用户不必分辨这排按钮是哪一档。
- 洗涤档位要成阶梯、档间等差。**按下取「松手后会变成的样子」**（即选中档），不跳过中间档——按下即预览结果。
- **有底色的改底色，没底色的改自身颜色**——同一个方向（往更醒目的一档走），只是对象不同。
- **状态的底色层与色阶是两件事，可以并存**：有自己方块点击区的控件可以既铺底又加深；嵌在别的控件里的小图标只加深不铺底，免得跟所在控件抢视觉。判断标准是**它有没有自己的方块点击区**，不是它叫什么。

**图标控件的状态色**（适用于所有「一枚图标自己就是个控件」的地方。）

四态从**同一条灰阶阶梯**取。阶梯自己是一组 token，**定义只在一处**，组件只引用、不写字面量。

| 态 | 取值方向 |
|---|---|
| 静置 | 基准灰 |
| 悬停 | 深一档 |
| 按下 | 再深一档 |
| 禁用 | **反方向退到更浅**（比静置还浅） |

- **禁用是「退到后面去」，不是「更醒目」**。这条容易写反：若顺手借了更深的灰，禁用态会比静置态还显眼，只能再压一层 `opacity` 补救——那是把补丁当设计。**不要用 `opacity` 表达「淡」**，全站应当一处都没有。
- **只加深，不变色相**：图标控件里不该有第二个色相。
- **整族共用一个底座**：同类图标控件共用一个基类，阶梯写在它上面，变体只写自己独有的东西。新增一个图标控件不要重抄这四档——挂进已有的族，或引用那四个 token。
- **图标控件不带语义色**：破坏性操作不靠颜色预警，改由**图标字形 + 动作时的确认弹窗**承担。确有需要上语义色的，必须写明理由并同步本节。
- **展开态 ≠ 悬停态**：控件展开时的高亮属于「选中语义」，不在悬停阶梯里。

**加载与选中**
- **loading**：加载中的按钮 = 前置转圈动画 + **真正的禁用**（置灰、鼠标键盘都点不动），**文字保持不变**——不改成「正在… / …中」。开关逻辑抽成一个函数（记住进入前的禁用状态、结束时还原），才能与「按条件禁用」叠加。
- **selected**：选中态 = 底色 + 强调字双信号，不只变一个色。

**状态指示必须来自真实状态**
- 进度条、完成标记、状态标签一律由**真实状态**推导，不用间接信号顶替——「某个文件在不在」「上一帧剩下的值」「默认值」这类信号，在真实状态还没发生时就已经成立，指示会**提前点亮**。这比不亮更糟：用户据此以为已经好了，然后对着一个没反应的界面等。
- 反方向同样要防：真实状态已经结束（完成 / 失败 / 被取消）时，指示必须跟着结束，不能停在「进行中」。
- **检查**：拿「还没开始 / 进行中 / 已完成 / 失败」四态逐个走一遍，看每一态下指示说的是不是真的。

## G5 动效（Motion）

**先答「该不该动」，再谈怎么做。**

| 这个操作一天发生几次 | 判据 |
|---|---|
| 上百次（快捷键、命令面板、高频切换） | **不动画。永远不动。** |
| 几十次（悬停、列表内移动） | 去掉，或压到几乎察觉不到 |
| 偶发（弹窗、抽屉、Toast、二级页） | 正常做 |
| 罕见 / 首次（引导、完成、庆祝） | 可以加一点惊喜 |

**键盘触发的动作一律不做动画**——它一天会发生几百次，动画只让它变慢、变迟钝。

**每个动效要能说出目的**：空间一致性（进出同源）/ 状态指示（变了什么）/ 解释（这东西怎么用）/ 反馈（听见了你的操作）/ 避免突兀（凭空出现会像坏了）。**说不出目的的就是装饰**，高频场景里不要。

**缓动治理**（场景 → 曲线的默认表见 `defaults.md`）

- 只有「进场」这条曲线需要自定义（`cubic-bezier(.215,.61,.355,1)` ≈ easeOutCubic），其余用内置关键字就够，别为了「整齐」都手写成曲线值——手写的越多越容易分家。
- **禁止用 `ease-in` 进场**：开头慢，而那一瞬正是用户盯得最紧的时候，读起来就是「迟钝」。
- **「更陡」有上限，过陡的 ease-out 就是「突兀」本身**：

  | 进场曲线 | 观感 |
  |---|---|
  | 内置 `ease-out` 关键字 | 偏弱、没分量 |
  | `cubic-bezier(.215,.61,.355,1)`（≈ easeOutCubic） | ✅ **目标档**：开头快、响应感在，位移摊得开 |
  | `cubic-bezier(.22,1,.36,1)`（≈ easeOutExpo） | ❌ 前 15% 时间就走完九成距离，看到的是「啪」一下 |

- **突兀的观感多半来自曲线，不是时长**：用户报「动效太快 / 太突然」时**先查曲线陡不陡，别急着加时长**。
- **全站只留一条进场曲线**（一个 token），不许一处一条。
- **多套动效实现必须同族**：CSS transition/keyframes、图表库（如 Chart.js 的 `easing`）、JS 动画库，三者的缓动**必须取自同一族、同一档**。CSS 换成 cubic 而图表库还留着 `easeOutQuart`，结果就是「页面入场柔和、图表入场却一激灵」。**改一处必须同步另一处**，审计时两边对账。

**空间与形态**
- **遮罩与内容同拍**：浮层变暗的遮罩和它里面的面板**同起同落、同时长**。只给面板配动效、遮罩直接切，会出现「背景先黑、面板后到」或「面板走了、黑还留着」——两截分开比不做动画还显眼。
- **进出同路径**：从右边进来的就从右边出去。消失方向与出现方向不一致，观感是断的。
- **浮层从触发它的元素长出来**：`transform-origin` 指触发点。**弹窗例外**——它不属于某个触发元素，居中即可。
- **不要从 `scale(0)` 出现**：没有东西是从「不存在」里冒出来的。起点用 `scale(.95)` 左右配 `opacity: 0`，或者干脆用位移。
- **进出场要「有方向」**：中间的每一帧都该暗示最终去哪儿，而不是盲目插值。

**实现选择**
- **用 transition，不用 keyframes**：transition 能被中途打断并改目标，keyframes 只能从头重放。keyframes 留给循环动画（转圈、呼吸）。
- **只动 `transform` / `opacity`**：改宽高、内外边距、`top / left` 会触发布局与重绘。要动位置用 `translate`，要动尺寸优先 `scale`。
- **动效 token 要拼好给人用**：时长与缓动各给档位，再给「拼好的组合」（如 `transition-fast`）——**不让人自己拼**，自己拼迟早拼出没进档位的组合（见 E1）。

**交接与降级**
- **速度要交出去**：拖拽结束后的动画要接着手指离开时的速度走，不要硬切到一段固定时长——中间那一下「顿」最容易被看出来。
- **减少动效不是取消反馈**：`prefers-reduced-motion` 下把位移 / 弹性降级成短的淡入淡出，而不是什么都不发生。
- **浮层之间互切要交叉过渡**，不留「只剩空遮罩」的那一帧（见 P6）。

## G6 度量治理（档位表见 `defaults.md`）

- **由几何反推的值必须写明出处**（如「为了让 A 与 B 对齐而算出来的数」）：改了就会错位，不写出处会被下一个人当成随手写的裸值清掉。
- **能用对齐方式做到的，就别用负外边距**——它会连点击区、悬停底色一起推出内容列。**两类正当的除外**：把「撑大的点击区」缩回原占位；给滚动容器留焦点环余量（见 P4）。每处都要写明属于哪一类。
- **间距同时承担成组**：同组内小档、相关组间中档、页面级大档。想让某元素重要，就放大它周围的间距——**分组靠间距，不靠画线**。
- **不单设「中标题 1.3」行高一档**——真觉得 1.2 挤，说明该调字号或间距，不是加一档行高。
- **改行高 token 前先查它推导出了哪些几何**：控件高度、图标按钮边长、行内间距可能全由它算出来，改一处要连带重算（在该 token 旁写明「改它要重算哪些」）。
- 数字数据（分数、计数、进度、统计）一律 `tabular-nums`，等宽避免跳动。
- **只有多行长段落才两端对齐**（`text-align: justify`）；短句与单行输入框不要加——单行文本永远算「最后一行」，加了也看不出变化。
- **加粗用少才有效**：需要层次时优先用字号与灰阶。一屏内加粗处应当一眼数得清。
- **不要把「选中」这类状态信号压在字重上**：小字号下常规与加粗的差异不足以承担状态，用户看不出差别等于没有信号（选中态走 G4 的底色 + 强调字）。
- **不追求大圆角，也不要 0 直角**（理由见 G10）；普通按钮 / 卡片 / 输入框不用全圆。

## G7 色彩系统（语义驱动）

| 语法 | 落地检查 |
|---|---|
| **色板分三层**：中性灰阶（打底与文字）+ 语义色阶（唯一 accent + 成功 / 警告 / 错误 / 信息）+ 档位色阶（评分星、等级这类有序档）。三层各司其职，不互借。 | 每层都能指出自己的职责；档位色没被当操作色用。 |
| **颜色全部来自色板 token**；无语义挪用（绿不表达错误、红不作成功），**一经建立不再互借**。 | token 定义之外无裸 hex / rgb；语义映射表固定且唯一。 |
| **语义族成套**：每族给 浅底 / 边框 / 本体 / 深字（需要叠透明度再补 rgb 三元组），规律统一。**缺一档就会出问题**——四个族都有「浅底上的深字」而 accent 没有时，选中态的字只能退回本体色，而本体色按白底校准，垫一层洗涤后就跌到达标线下，成了全站唯一不达标的一族。 | 语义 token 命名成族，删补成套；对照度表逐族核过。 |
| **底与字分工**：色块 / 进度 / 按钮底用本体色（base）；**坐在自家浅底上的文字必须用深字档（strong）**。 | 白底档位 / 状态文字引用 strong 档。 |
| **对比度按「实际所在底色」校准，不是按白底**：同一个灰 / 色名垫到浅底上会掉一档，很多不达标就是这么来的。 | 关键文字对逐个用它**真正坐在上面**的底色算过；同一色值出现在两种底色上时，两种都过。 |
| **命名要能自解释**：同族里「浅一档（给实心底悬停用）」与「深一档（给浅底上的字、描边悬停用）」并存时，名字必须一眼分得清方向。 | 看到名字不必回文档就能判断方向；混用处为零。 |
| **语义提示用「浅底 + 深字」双通道，不配语义描边 token**：轮廓线交给留白。 | 语义族只有三档，没有 `--border-*` 语义描边。 |
| **档位色只作档位**，不作操作色 / 警示色；警示一律走警告或错误。 | 档位色不出现在按钮与提示条上。 |
| **主 / 次 / 危险按钮**：主行动 = 主色实心；次要 = 描边 / 幽灵；危险 = 红实心仅限破坏性确认位。一屏一个实心主按钮。 | 主 CTA 视觉最实；危险动作不贴着主 CTA。 |
| **状态不只靠颜色（冗余编码）**：错误 / 必选 / 选中等状态在变色之外必须有图标或文字。 | 错误输入 = 红描边 + 提示语；必选 = 标记 + 校验提示。 |
| **对比度底线**：正文与重要标签 ≥ 4.5:1，大字 / 粗体 ≥ 3:1。 | 关键文字对用对比度工具算过。 |

**辅助**：中英文间留空格、夹中文的英文标点用中文标点。

## G8 组件几何

**按钮：身高定字号，文字不「撑」按钮**
- 控件高度决定它内部能放多大的字。经验比例：按钮文字字号 / 按钮高度 ≈ **0.39–0.44**，越大越接近上限；**超过约 40% 就该加高度，不是把字塞进矮按钮**。
- 字号表里最大的两档**不进按钮**。
- 按钮内图标比的是**墨迹**不是盒子：**墨迹高 ≲ 字号 × 1.1**，与文字间距 ≥ 4px。（图标库的画布自带留白，按盒子边长去卡这条会把已经光学调过的图标误判成超标，反过来把它改小。）

**按钮排列：鼓励靠右、危险靠左**
- 普通动作（保存 / 确定 / 开始）：主动作放**最右**，取消在左。
- 危险动作（删除 / 清空）：放**偏左**，与主 CTA 拉开——**但「偏左」不必然是第一个**，它可以排第二，只要不在最右。
- 鼓励动作视觉更实（实心主色），不与危险按钮做对等的对称样式。红实心只出现在确认弹窗的破坏性「确定」位，普通界面不放。
- **间距是「盒子相等」，视觉上并不相等**：可点区是盒子、图形只占中间一块的控件（图标钮），与紧邻的实心 / 描边控件之间，视觉间距会被「吃掉」——图标那侧是盒子边到墨迹边，实心钮那侧是盒子边到盒子边。同一个 `gap`，「图标 → 实心钮」显挤、「图标 → 图标」显松。按墨迹宽两侧各校正一档。
- **当前批次不能删除时，按钮照常占位走禁用态**：只删按钮会让每行末端结构不一致、图标位置来回跳。禁用理由写进 `aria-label`。

**其他**
- **只读展示不许长得像可输入**：只读值用更弱的底、无描边、辅助字色、更小字号，比相邻输入框明显弱一档；长值省略号收尾，不把整行撑变形。
- **弹窗内容多时只在自身高度内滚动**，标题与底部按钮固定不动。给滚动区留焦点环余量见 P4。
- **提示条用语义浅底 + 深字，不带描边**；底色一律取语义 token，不手写半透明洗涤——同一类提示只有一种写法。
- **空态要有**：居中、辅助字色、多行说明用舒展行高（空态的三条内容要求见 G2）。
- **相邻可选项之间要留缝**：下拉项、分段钮这类紧挨着的可点面，两片同色底一旦相接（悬停底色挨着选中底色）就糊成一块，看不出是哪一项。**留一条缝**，或让各自的底色圆角收进去。

## G9 图标规范（Iconography Governance）

**选型**
- **按产品类型与平台选一套图标库并固定**（线宽风格、权重档、许可）。**同一产品只能使用同一套功能图标**，不混多库；同一套库内也只取**同一风格档**（统一权重 / 填充方式）。
- **尺寸、线宽、间距统一**（做成 token / 常量，不随手改）；**档位绑死角色**，取用时按角色选、不按「看着差不多」选。
- **标称尺寸普遍比文字大一号**：图标库的画布按统一格数归一化，墨迹只占其中一部分、四周自带留白。拿标称值去对字号会一直觉得别扭——**先想起这条**。（默认尺寸五档见 `defaults.md`。）

**对齐**
- **对齐比的是墨迹，不是盒子**：判断用「高」不用「宽」；同一行几枚图标的墨迹占比不同时，允许在同一档内做小幅微调，目的是**墨迹等高**。**每处微调都要写明理由**，否则下一个人看到同一行两个尺寸会当成没做完。
- **图标与中文同一行时，垂直方向要对齐文字的「墨迹中线」**：中文在字体行框里比中线略低一点，只做盒子居中会让图标看着偏高半个像素，上下对称的图标最明显。做法是给该行图标一个随字号走的光学补偿，不是把图标盒撑高、也不改行高。
- **对齐要量，不要目测**：`getBoundingClientRect()` 取图标墨迹的中线、与相邻文字行框的中线相减，**差值 > 0.5px 就算没对齐**，补补偿值再量一次。目测会漏掉「每处都差一点点」——单看每一处都还行，整屏扫过去就是「图标位置怪怪的」。同一行有几枚图标时，先保证彼此墨迹等高，再一起对文字中线。
- **菜单项、下拉项这类「行」不受按钮比例约束**：行有整行高度和留白可用，图标可以取大一点。只有**按钮内**图标要守 G8 的比例。

**实现**
- **图标统一进 symbol 库 / 图标组件**，用引用方式使用，界面不散落路径。
- 调用处的视口尺寸与库内部的坐标系是两件事——符号库会把内部坐标系缩放适配到调用处的视口，**调用处照常写常规视口即可，不必按库的内部格数换算**。官方路径**一个字符都别手改**。
- **实心 / 空心的判据是「这枚字形有没有能看的细线版」，不是「它重不重要」**：播放三角、暂停双杠这类本身就是实心几何，取线形只会得到细描边、小尺寸下糊成一团。新增实心图标先确认它落在「字形本身没有可读线形」或「需要比旁边重一级的强调」两类里，并在取用处写明理由。
- 颜色跟随 `currentColor`；方向箭头由 CSS `rotate()` 转向，不写字形字符。

**点击目标**
- **不小于 24×24**：图标可以只有 12–18，但可点区要撑到 24（触屏更大，见 G3）。两种撑法，看该元素周围要不要留白——直接做一个够大的盒子（图标居中）；或做大盒子再**配负外边距把占位缩回原尺寸**，视觉位置与间距一动不动、四周各多出一圈可点区。
- **浮层要锚在被锚元素盒子的「中线」而不是边缘**：图标在盒内居中，中线与盒子尺寸无关，盒子改成多大偏移都仍然正确；锚边缘则每次改盒子尺寸都要重算一遍（见 P9）。

**禁止**
- **禁止 Emoji 当功能图标**（Emoji 是字体不是图标，跨端渲染不一致）。
- **禁止用 Unicode 字符代替图标**（▸ ▾ ✔ ❌ 这类字形不是图标）。
- **禁止临时生成内联 SVG 当图标**（画风难统一、难维护）。
- **找不到图标时选同库近义图标**，不为省事退回字符或自绘。
- **不用 `opacity` 表达「淡」**，走状态色阶梯（见 G4）。

## G10 造型口味（默认，可被 B 覆盖）

默认阴影三档见 `defaults.md`。治理规则：

- **阴影承载浮起层级，不作装饰**：中性暗调、低透明，宁浅勿深。
- **浮层描边取最浅档**：分层交给阴影，描边只负责勾出边界。
- 深色模式下阴影基本不可见，**改用描边分层**（见 defaults）。
- **状态发光是唯一例外**：状态点光晕、选中高光、主 CTA 的悬停影用语义色叠低 alpha，表达「发光 / 选中」，不是浮起层级。**除主 CTA 外，按钮悬停不给影**（见 G4 悬停总则）。
- **圆角克制**（见 defaults / G6），不做超大圆角、不做 0 直角；不做高饱和渐变、不引入第二彩色 accent。

## G11 数据可视化（图表）

**图表不是「画出来就行」。** 在数据类产品里，图表占的面积往往比正文还大，**它的一致性比组件更值得先定**——而它最容易被当成「技术活」跳过，各处各写各的配置。

### G11.1 选型（B1 必问，别自己定）

- **一套库、一个版本，全站固定。** 中途换库 = 所有图表配置重写。选型看四件事：
  ① **技术栈**（原生 HTML 用 Chart.js / ECharts，React 用 Recharts / visx）；
  ② **数据量**（上千个点要能走 canvas 或抽稀，纯 SVG 建 DOM 会卡死）；
  ③ **需要的图型**（地图、桑基、关系图、雷达只有 ECharts / D3 这类有）；
  ④ **体积与离线**（本地化后多大、断网能不能跑）。
- **配置写法也要统一**：不要一处 `new Chart(...)`、一处写配置对象。**抽一层自己的封装**，颜色 / 字号 / 网格线 / tooltip / 动效**全部走封装**，调用处只传数据。没有封装层的项目，图表配置一定会散落各处、各写各的。
- **别混多套图表库**：Chart.js 和 ECharts 并存时，tooltip 样式、动效曲线、响应式行为三处最先露馅。

### G11.2 图型选择

| 要表达什么 | 用什么 | 不要用什么 |
|---|---|---|
| 比大小（分类不多） | 柱 / 条形 | 饼图 |
| 看趋势（时间序列） | 折线 | 柱（点多时糊成一片） |
| 看占比（分类 ≤ 5） | 饼 / 环 | 饼（> 5 类） |
| 看构成随时间变 | 堆叠柱 / 堆叠面积 | 多张饼 |
| 看分布 | 直方 / 箱线 | 折线 |
| 看相关性 | 散点 | 折线 |
| 看二维交叉（部门 × 等级） | 热力矩阵 | 一堆小饼 |

- **分类超过 6–7 类就别用饼图**：人眼比角度不准，扇形一多就分不清。改**横向条形**（还能顺带排序）。
- **分类名是中文、或名字长时用横向条形**（`indexAxis:'y'`）：横排不用把标签转 45°。
- **一屏一个「主图」**：并排四五个同等大小的图，等于没有重点。

### G11.3 坐标轴与网格线

- **能去掉的都去掉**：纵轴刻度线、外框、绘图区背景色一律不加。**网格线只留水平**——纵向网格线几乎总是噪音。
- **坐标轴不是数据，用最浅的灰**（专门的 `gridline` / `baseline` 令牌），**不要用正文色**。
- **数值轴从 0 起**（柱状图必须；折线图要强调变化幅度时可以截断，但**必须在轴上标出来**）。
- **分类多时标签抽稀**（每 N 个显示一个），别让标签叠成一团。

### G11.4 图例与标注

- **单序列不要图例**——标题已经说了这是什么。
- **图例位置全站固定**（都在顶部，或都在底部），不要这张在右、那张在下。
- **能直接标在图上就别用图例**（折线末端直接写名字），省掉「看图例 → 回图上找」的来回。
- **数据标签只在点少时开**（≤ 12 个点）。点多了标签互相压，改成 hover 出 tooltip。

### G11.5 配色

- **图表填充取分类色板，语义色专留给语义。**「离职率」这类带好坏方向的才用红绿；**别拿红绿当两个普通分类**——用户会读成「这个好那个坏」。
- **同一张图内相邻色 ΔE 要够大**（≥ 15，用 CIEDE2000 算）。分类色板是**按彼此距离**挑的，但**按 `palette[0..n]` 顺序取前 N 个最容易拿到两个相近色**——要**按用途挑色**，不是按顺序取。校验脚本：逐图打印最小 ΔE。
- **有顺序的档位（评分、等级、到期强度）用档位色阶**，不用分类色板（见 G7 三层色板）。
- **深色模式要另给色值**：同一个分类色垫到深底上会掉一档，别指望浅色的值自动可用。
- **条内文字颜色按「这一条自己的底色」判**，不是按主题——深色模式里条底可能是提亮过的浅色，写死白字会读不清。按主题缓存结果，别每帧读 `getComputedStyle`（`afterDatasetsDraw` 每帧都跑）。

### G11.6 状态与退化

- **三态齐全**：空态（给下一步动作）、加载态、错误态。**空态不要画一个空坐标系**。
- **单点数据不要画折线**（一个点连不成线）：退化成「一个点 + 数值」，或直接显示数字。
- **全部为 0 时给一句话说明**，别画一排高度为 0 的柱子。
- **数值超长时缩写或省略**（`12.3万`），别让标签撑破卡片。
- **图表的空态文案要与页面其他空态同款**（同一个 `renderEmpty()` 之类），别图表一套、列表一套。

### G11.7 动效与无障碍

- **图表入场走 `slow` 档、与页面入场同族缓动**（见 G5）；**键盘触发的切换不做动画**。
- **图表不能是唯一的信息通道**：关键数值要在图旁用文字重复一次，否则读屏用户与色盲用户都拿不到。
- **canvas 要给可访问名**：`role="img"` + `aria-label` **概括结论**（「各部门在职人数，研发 120 人最高」），不是只写「柱状图」。旁边若有明细表，用 `aria-describedby` 指过去。
- **图表可点时**，它算「有底色的可点面」，走 G4 悬停总则；但**按下态可以不给**——真正被按的是图里的那一条，给整块加底色/缩放会把「我点的是这条」这个信息抹掉（**这条例外要写明理由**）。

## G12 无障碍（可及性）
| 语法 | 落地检查 |
|---|---|
| **键盘可达**：所有功能 Tab 可达并可用 Enter / 空格 / 方向键操作；焦点遍历顺序符合视觉阅读顺序，不跳焦点。 | 全交互过一遍 Tab 序；焦点环可见。 |
| **焦点环一律可见**：键盘到达时必现，鼠标点击时不显示。程序聚焦的定位标题 / 弹窗（非交互控件）只是读屏落点，不画环。滚动容器里的环要留出余量（见 P4）。 | 逐个可 Tab 元素聚焦看一眼；滚动容器内重点查。 |
| **不只靠颜色**（见 G7）：状态差异双通道。 | 错误 / 必选 / 连接状态都有文字或图标相伴。 |
| **读屏属性**：纯图标按钮有 `aria-label`，装饰图标 `aria-hidden`，展开用 `aria-expanded`，动态提示用 live region，弹窗 `role=dialog` + `aria-modal`。**不给原生 `title`**——它会弹系统气泡，且不该用来承载必需信息。 | a11y 语义属性齐；全局搜一遍 `title=`。 |
| **live region 不能嵌套**（见 P8）。 | 容器与元素只有一层标了 live region。 |
| **文字可选中**：正文默认可选中复制，仅交互元素禁用选择。 | 随机划一段正文确认能选中。 |
| **动效尊重 `prefers-reduced-motion`**：关闭或降级为淡入淡出（见 G5）。 | reduced-motion 媒体查询生效。 |
| **命中目标**（尺寸与撑法见 G3 / G9）。 | 最小控件过一遍。 |
