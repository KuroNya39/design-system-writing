# 实现陷阱（P1–P16）

**这不是审美取舍，是接下来一定会撞上的工程事实。** 每条给「现象 → 为什么 → 做法 → 检查」。

### P1 浏览器默认样式的反扑
- **现象**：控件的高度、字号、行高不受 token 管，改了 token 它不动，换个字体它又跟着变。
- **为什么**：元素的浏览器默认样式用简写属性（如 `font`）一次性重置了行高、字号、字族，控件上不写就落回默认值（不同字体下默认行高不同）。
- **做法**：**兜底写在元素选择器的重置里**，一次管住所有同类元素，将来新加的漏不掉；想另给值的类照样盖得住。
- **检查**：同类元素是不是每个都单独补过一次？补了 N 次，说明该写进重置。

### P2 `:hover` 靠不住的场合
- **现象**：按住 / 拖动时，本该出现的那层反馈色凭空消失。
- **为什么**：**指针捕获期间，浏览器把 `:hover` 归给捕获元素**，被捕获区域内其它元素的悬停状态整个失效。
- **做法**：任何「按下 / 拖动中」的观感都不能靠 `:hover`，由脚本挂状态类。
- **检查**：拖动 / 长按路径上的反馈是不是 CSS 伪类？真机按住（而非模拟点击）测一次。

### P3 自绘滚动条是 CSS + JS 两半
- **现象**：「鼠标移入才显示」的滚动条时有时无；样式算得对、屏幕上是旧的。
- **为什么**：某些浏览器**不因容器自身的 `:hover` 变化重画它自己的自定义滚动条**（滚动条独立成层，悬停失效传不进去）。
- **做法**：样式管颜色与粗细，脚本在进出容器时触发一次重画，**缺一不成**。
- **例外**：表单控件（多行输入框之类）的滚动条画在元素自己的绘制里，没有这个毛病、不需要那一半——别照着它把脚本判成多余。
- **检查**：只写了样式没写重画？反之，给表单控件多写了脚本？

### P4 焦点环被滚动容器裁切
- **现象**：滚动容器里的控件聚焦时，焦点环左右两侧被切平。
- **为什么**：焦点环是**向外**画的阴影，而滚动容器的**裁切线是它的内距盒**——无边框时内距盒就等于边框盒外缘。所以**给容器加左右内距是没用的**，内距盒不因内距向外长。
- **做法**：给**容器自己**挂等量**负外边距**：边框盒连同裁切线一起向外撑，内容盒再被内距推回原位，子元素位置一个像素不动。**内距与负外边距是一对、必须同值**，只改一个会多出一条横向滚动条。
- **检查**：滚动容器里第一个 / 最后一个控件聚焦，环是否完整。

### P5 样式权重战争
- **现象**：某个变体的样式「压是压得住」，但一挪位置、或者谁再给它加一个类，就悄没声地失效了。
- **为什么**：靠叠加一个类去提权、压住另一条选择器的写法是脆的——它依赖类的数量，而类数量会随重构变化。
- **做法**：让该变体**自成一档**，它自己的底色、尺寸、全部状态写在自己一个类里，不去压任何人。
- **推论**：**没有第二个用户的档位就是没人用的档位**，留着只会让人以为可以随手加，该删。
- **检查**：全局搜有没有「为了盖住别人」而叠类的地方。

### P6 浮层互切要交叉过渡
- **现象**：从一个浮层跳到另一个浮层时，中间闪一下白底 / 背景。用户会反复报这个。
- **为什么**：写成「先关旧的、再开新的」，两段淡入淡出之间必然露出一帧背景。
- **做法**：交叉过渡——旧层的遮罩**留在原地撑住明暗**、面板淡出，新层以透明遮罩浮上来同步淡入，全程没有「只剩空遮罩」的那一帧。
- **检查**：逐对测浮层跳转，慢放看有没有空帧。

### P7 点遮罩关闭要判「按下与松开同源」
- **现象**：在弹窗内的长输入框里按住拖动，松手时弹窗关了。
- **为什么**：只判 `click` 事件的 `target` 会误杀——指针移出后，事件会派发到**按下点与松开点的共同祖先**，正是遮罩本身。
- **做法**：记住按下点，只有**按下与松开都落在遮罩上**才算数。
- **检查**：在弹窗内的多行输入框里按住拖到框外再松手。

### P8 live region 不能嵌套
- **现象**：同一条提示被读屏念两遍。
- **为什么**：容器标了 live region，每条提示自己又标一次。
- **做法**：让**最内层的提示元素自己带**，容器不标。
- **检查**：容器与元素是否都标了。

### P9 浮层锚点锚中线，不锚边缘
- **现象**：被锚元素（图标盒）尺寸一改，浮层位置就偏，每次都得重算偏移量。
- **做法**：锚在它的**中线**上——图标在盒内居中，中线与盒子尺寸无关，盒子改成多大偏移都仍然正确。
- **检查**：有没有 `calc(100% + Npx)` 这类锚边缘、且旁边写着「改盒高要同步改这里」的注释。

### P10 拆样式 / 脚本文件后的加载顺序
- **规则**：把一份样式拆成多个文件时，**HTML 里的加载顺序就是拆分前文件内的顺序**，勿调换——顺序即语义，级联结果会变。脚本同理：多个小文件按顺序共享作用域时，顺序不能调。
- **拆分只做「分桶」，不做「按功能重新归属」**：按「文件名 = 功能」去找选择器会找错地方。在每个文件里放分节 banner，检索靠它。
- **落地**：文档里写明「级联顺序的唯一权威是 HTML 的加载顺序」，并列出每个文件装了哪几节。
- **检查**：有没有人因为「看着更整齐」重排过加载顺序。

### P11 可中断的动效别用 keyframes
- **现象**：「关到一半又点开」的对象，先跳回起点再重放，而不是从当前位置接着走。
- **为什么**：keyframes 每次触发都从头播；transition 才会从**当前值**重新起步。
- **做法**：能被打断的 UI 动效用 transition（或弹簧），keyframes 只留给循环动画。
- **检查**：把每个弹窗 / 抽屉 / Toast 在中途重触发一次，看有没有跳变。

### P12 焦点在元素消失时丢掉
- **现象**：删掉一行 / 一个标签 / 关掉一个内联面板之后，键盘再按 Tab 从页面开头重来，或焦点落到看不见的地方。
- **为什么**：焦点跟着被删掉的元素一起没了，浏览器只能把焦点抛回 `body`。
- **做法**：删除前先算好「焦点该去哪儿」（上下邻居 / 容器 / 触发按钮），删完立刻把焦点送过去；弹窗关闭时还给触发它的元素。
- **检查**：只用键盘做一次删除，看焦点落在哪儿。

### P13 别在元素不可见时量尺寸
- **现象**：自绘的指示条 / 滑块平时位置都对，窗口一缩放就缩成 0 宽或跳到最左边，再也回不来；刷新一下又好了。
- **为什么**：它「被隐藏」的那一刻正好赶上一次重新测量（缩放、布局变化触发的），量到的是 0——**不可见元素量出来的尺寸恒为 0**——而这个 0 被当成真实值写了回去。
- **做法**：写回之前先确认元素可见（父级没被隐藏、没 `display: none`）；确实需要隐藏的，**恢复可见的那一帧补量一次**，别指望隐藏期间量到的值还作数。
- **检查**：把每个「量完再写回」的地方过一遍——触发测量的那些时机里，元素有没有可能正被隐藏。

### P14 内容撑高的浮层要「数据到手才开窗」
- **现象**：打开历史记录 / 列表类弹窗时，先闪出一个很矮的空盒子，再「啪」地弹到应有高度。
- **为什么**：浮层高度由内容撑出来，而开窗动作发生在数据到位之前——先拿空内容渲染一次量到高度，数据填进来又得重新量，两次高度都是真的，于是看起来就是「弹开」。
- **做法**：**数据到手再开窗**。必须立刻给反馈时，先用固定高度或骨架占位，并且让**清空与填充在同一帧里完成**，中间不留「空内容已渲染、数据还没填」的那一帧。
- **检查**：慢放打开过程，有没有「先小后大」的跳变。

### P15 别用「重叠 + 遮挡」伪造形状
- **现象**：气泡的尖角（一个方块转 45° 塞在气泡底下、用气泡底色盖掉一半）在淡入时那一块颜色明显更深；换主题色时尖角还跟气泡对不上。
- **为什么**：遮挡靠的是「上面那层不透明」。只要上层沾了一点透明度——淡入过程中的任意一帧、半透明底色、`opacity` 动画——两层就叠在一起算颜色，重叠处 = 两层相加。
- **做法**：两条出路——① 形状用**一条路径**画完（`clip-path` 或 SVG），从根上不存在重叠；② 确实要叠，就让淡入发生在**包住这两层的父元素**上，别让两层各自淡入。
- **检查**：搜「转 45° 塞一个角」这类写法；把浮层淡入慢放，看重叠处有没有更深的一块。

### P16 系统 / 浏览器原生 UI 不受你的 token 管
- **现象**：自绘了一整套输入框，右键弹出来的却是系统菜单——字体、圆角、配色跟别处完全两套。原生下拉、文件选择框、滚动条同理。
- **为什么**：这些界面由浏览器或操作系统绘制，不在你的 DOM 里，CSS 与 token 都够不着。
- **做法**：**默认接管，接受原生才是需要写理由的例外**。不要默认「留着原生的，反正能用」——那正是规范里查不到的第三种样式。
  - **`<select>` / `<option>` 是头号目标**：它是「看起来能改、其实改不动」的典型（`appearance:none` 只改得了收起时的框，展开的那一列仍由系统绘制）。**要一致就得整个换掉**——触发器自绘 + 选项列表自建（走同一批 token、同一套悬停/选中态、同一套圆角与影）。这条最容易被漏，因为不展开看不出来。
  - 同类还有：`checkbox` / `radio` / `date` / `file` 选择器、右键菜单、`<dialog>` 默认样式、滚动条。**能自绘就自绘**；确实要留原生的（如日期面板、文件选择器），在规范里逐条写明「这几处是原生的，不属于本体系」并给出理由。
- **检查**：① 全站搜 `select` / `input[type=checkbox]` / `input[type=radio]` / `input[type=date]` / `input[type=file]`，逐个标记「已接管 / 已记录理由」，**不允许既没接管也没记录**；② 挨个**展开**一次（下拉要真的点开、日期要真的弹出），看有没有体系外的样式；③ 右键一次。
