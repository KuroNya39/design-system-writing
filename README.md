# design-system-writing

为软件项目建立 / 维护 UI 设计系统（Claude Code Skill，半自动设计系统工程师）。

AI 先侦察项目：盘点界面与语义、把不统一点列成带 `file:line` 的档案；内置可复用的「设计语法」取舍准则（单列优先 / 语义色彩 / 8pt 栅格 / 完整状态组 / 键盘可达 / 图标治理等）；再落地为设计 token + 组件规格表 + 规范文档，只把审美取舍（气质 / 主色 / 图标库）抛给你判断。

## 安装

```bash
# Skill 名 = 目录名 design-system-writing
mkdir -p ~/.claude/skills/design-system-writing
cp SKILL.md ~/.claude/skills/design-system-writing/SKILL.md
```

装好后在对话里输入 `/design-system-writing` 即可调用。

## 适用场景

- 项目还没有设计系统，界面配色 / 间距 / 字号靠手感——建一份 `design-system.md` + 设计 token 当单一依据
- 已有规范，改了 UI / 新增设计 token 后回来同步
- 要改界面前，拿一份「照这个做、别自己发明」的约束，避免风格漂移
- 界面被指出不统一：同样控件两个样、颜色乱、图标混用

## 工作方式

按 A–F 六个阶段推进，全程半自动：

- **A · 项目侦察** —— 识别技术栈与样式方案、盘点界面与语义，不统一点列成带 `file:line` 的档案。
- **B · 决策轮** —— 只问审美取舍（气质 / 主色 / 图标库），每题带推荐答案，可「全按推荐」。
- **C · 设计语法** —— 内置可复用取舍准则：单列优先 / 渐进披露 / 8pt 栅格 / 语义色彩 / 完整状态组 / 键盘可达 / 图标治理。
- **D · 落地实现** —— 按技术栈落地：设计 token（primitive → semantic）＋ 组件规格表 ＋ 规范文档。
- **E · 校验审计** —— 静态扫裸值 / 非档位值 / 状态残缺；规范 ↔ token ↔ 代码三方一致。
- **F · 交付维护** —— 交付审计报告；新增 / 改 token 走四步流程。

## 目录

- `SKILL.md` —— 阶段 A–F 全文（侦察清单、决策轮、设计语法、token 与组件规格方法论、审计与维护）
