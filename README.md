# design-system-writing

为软件项目建立 / 维护 UI 设计系统（Claude Code Skill，半自动设计系统工程师）。

AI 先侦察项目：盘点界面与语义、把不统一点列成带 `file:line` 的档案；内置两套可复用规则集：「设计语法」（单列优先 / 语义色彩 / 间距网格 / 行高与字重治理 / 悬停总则 / 组件几何 / 图标治理等取舍准则）与「实现陷阱」（浏览器默认样式反扑、伪类失效、滚动条与焦点环、样式权重战争等踩过才知道的坑）；再落地为设计 token + 组件规格表 + 规范文档，只把审美取舍（气质 / 主色 / 图标库）抛给你判断。

## 安装

```bash
# Skill 名 = 目录名 design-system-writing
mkdir -p ~/.claude/skills/design-system-writing
cp SKILL.md ~/.claude/skills/design-system-writing/SKILL.md
```

装好后在对话里输入 `/design-system-writing` 即可调用。

## 适用场景

- 项目还没有设计系统，界面配色 / 间距 / 字号靠手感——建一份 `design-system.md` + 设计 token 当单一依据
- 已有规范，改了 UI / 新增设计 token 后回来同步
- 要改界面前，拿一份「照这个做、别自己发明」的约束，避免风格漂移
- 界面被指出不统一：同样控件两个样、颜色乱、图标混用

## 工作方式

按 A–G 七个阶段推进，全程半自动：

- **A · 项目侦察** —— 识别技术栈与样式方案、盘点界面与语义，不统一点列成带 `file:line` 的档案。
- **B · 决策轮** —— 只问审美取舍（气质 / 主色 / 图标库 / 尺寸档位），每题带推荐答案，可「全按推荐」。
- **C · 设计语法** —— 内置取舍准则：单列优先 / 渐进披露 / 间距网格 / 语义色彩 / 行高与字重 / 完整状态组 / 悬停总则 / 组件几何 / 图标治理 / 无障碍 / 造型口味。
- **D · 实现陷阱** —— 十类「踩过才知道」的工程坑：浏览器默认样式反扑、伪类失效、滚动条与焦点环、样式权重战争、浮层互切与遮罩判定等，每条给现象 / 原因 / 做法 / 检查。
- **E · 落地实现** —— 按技术栈落地：设计 token（primitive → semantic）＋ 组件规格表 ＋ 规范文档。
- **F · 校验审计** —— 静态扫裸值 / 非档位值 / 状态残缺；规范 ↔ token ↔ 代码三方一致；浮层互切、滚动容器焦点环等专项复测。
- **G · 交付维护** —— 交付审计报告；新增 / 改 token 走五步流程（第一步先查旧 token 有没有人用）。

## 目录
